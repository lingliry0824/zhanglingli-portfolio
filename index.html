01 · 流程设计

设计七阶段可控生成工作流，明确各阶段输入输出与异常兜底规则，替代单轮续写模式。

02 · 框架设计

基于 nano-cc Harness 落地状态管理、工具调用、流程编排、运行日志 4 个核心模块；设计结构化状态库、事件时间线、向量语义记忆三类存储，通过动态召回平衡一致性与 Token 成本。

03 · 评测搭建

构建 50 组连续生成评测任务集，标注约束条件与判定标准；采用 LLM-as-a-Judge 结合人工抽检交叉验证，从 4 个维度量化生成效果。

04 · 效果迭代

定位 4 类典型失败原因，定向优化记忆路由与修订 Prompt，实现各项指标提升与 Token 成本下降。

CASE 02 · OPEN-SOURCE PRACTICE (AGPL-3.0) 2026

CyberBoss · 微信里的 AI 生活助理

个人实践 · 基于开源项目的本地部署与深度配置

把 Codex / Claude Code 接进微信，让 Agent 拥有时间感、行踪感和主动唤醒能力：它记得你上次说话是几点，会在随机时刻主动出现，会写日记、补时间轴，也会在你失联时催你起床。

我的角色

本地部署与微信扫码接入、人格与工作区配置、工具链调试与持续使用。

微信消息→ HTTP Bridge→ 加时间戳→ Codex / Claude Code→ MCP 工具→ 微信回复
01

绝对时间感

每条消息进入 runtime 前自动加本地时间戳，判断内容与沉默时长。

02

随机唤醒 checkin

随机区间主动唤醒模型，由其决定提醒、催促、写日记或查状态。

03

生活时间轴

从碎片聊天补全事件起止与时长，重构结构化时间轴与「处刑报表」。

04

Zero-Token 日记

纯本地文件日记，不调用模型、不依赖云服务，也不消耗上下文。

05

行踪感 whereabouts

内置 MCP 接收定位、电量与触发原因，可查当前停留与近期移动。

06

提醒队列

模型留给「未来的自己」的任务：约定未回消息即可调 MCP 干预。

07

MCP 与本地工具

发文件、表情包、系统消息、时间轴截图，可接本地硬件与软件。

08

视觉输入

auto / caption / native / off 四种模式，文本模型也能看懂图片。

09

共享线程

微信与终端连着同一条 runtime 线程，随时在电脑上接手对话。

10

多账号与白名单

扫码登录、多账号切换，用 allowed user IDs 控制访问权限。

技术栈：Node.js 22+ · Codex / Claude Code 双 runtime · 微信 HTTP Bridge · MCP · 本地 JSON 状态
